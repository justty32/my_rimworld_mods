# npc-outposts O1 設計 spec：NPC 派系哨站（世界的血肉）

> 可行性權威：`pas/analysis/rimworld_mods/_mod_ideas/world_map_grand_strategy/02_outposts_and_world_objects.md`（VOE 解剖、輕量 WorldObject、lazy 生圖）。
> 反編譯權威源：`C:\code\mine\pas\projects\rimworld`（1.6 本體）。本文引用一律 `path:line`。
> 本 spec 含一個對 sims-mode-community 的附帶交付（§7「真訪問」），實作時 commit 到該 mod。

## 1. 目標與路線圖定位

NPC 派系的聚落周圍會有**哨站**（衛星式小型據點）：大地圖上看得到、可拜訪（小地圖+有作息的守軍）、可交易、可攻打。世界隨時間長出新哨站，讓派系有「活著、在經營領地」的感覺。

整體路線圖（每階段獨立 spec）：
- **O1（本案）＝世界的血肉**：哨站物件 + 開局鋪設 + 隨時間增生 + 拜訪/交易/攻打。
- **O2＝功能性節點**：哨站類型實質化（礦場/伐木場/軍哨/補給站，不同風味與守軍 profile）。
- **O3＝可搶的戰略目標**：擊破後果（戰利品表、派系報復、關係效果深化）。
- **延後（等使用者提供 Rim War / Empire Refactor 參考）**：哨站對母聚落的數值增益（人口、金錢、戰力）。O1 只留接點（§4 母聚落引用、§5 OutpostTypeDef 可擴欄位）。

## 2. 範圍（O1）

### 做
- `NpcOutpost : Settlement` 世界物件：可拜訪（生成小號聚落圖）、可交易（原版聚落同款）、可攻打（小圖+原版關係懲罰）、被擊敗即移除。
- 開局 `WorldGenStep` 鋪基底 + `WorldComponent` 隨時間補鋪（同一條鋪設邏輯，兩個觸發點；舊檔中途裝 mod 自然長出哨站）。
- Def 體系：`OutpostTypeDef`（O1 一種泛用型）+ `OutpostProfileDef`（派系維度，resolver 同 sims-mode 模式）。零寫死，供其他 mod patch。
- sims-mode 側附帶交付：「真訪問」原版聚落（§7）。

### 砍掉（YAGNI）
- 哨站→母聚落數值增益（等參考 mod）。
- 哨站類型差異化內容（O2）、戰利品/報復系統（O3）、哨站被 NPC 互相攻打、哨站消亡/遷移、玩家奪取哨站改旗易幟。
- 自訂營地佈局生成——地圖**共用 sims-mode 那條線**（§4），不自寫 GenStep。

## 3. 架構總覽

```
npc-outposts（新 mod，硬相依 sims-mode-community）
├─ NpcOutpost : Settlement            ← 白嫖 visit/trade/attack/defeat 全套
│   ├─ override GetFloatMenuOptions / GetCaravanGizmos
│   │     攻擊 → 自己的小圖 attack 流程（複用 SettlementUtility.AffectRelationsOnAttacked）
│   │     拜訪 → 共用 sims-mode 的 ArrivalAction（§7，assembly 引用）
│   └─ parentSettlement 引用（增益系統接點）
├─ OutpostTypeDef / OutpostProfileDef + resolver   ← 全資料驅動
├─ WorldGenStep_NpcOutposts            ← 開局鋪基底
└─ WorldComponent_OutpostSpawner       ← 隨時間補鋪（MTB 機率制）

地圖生成：零自寫。MapGeneratorDef = 原版 Base_Faction
→ sims-mode patch 的 GenStep_SettlementLife 自動生效 → 哨站守軍有角色作息。
```

- namespace `pas.outposts`，defName 前綴 `pas_outposts_`，packageId `pas.outposts.community`。
- About.xml `modDependencies` + `loadAfter` 指向 `pas.sims.community`；csproj 引用 `SimsModeCommunity.dll`。
- 零 Harmony（延續 sims-mode 目標）：所有行為改寫都在自己的子類 override 與 XML patch 內完成。

## 4. 世界物件：NpcOutpost

繼承 `Settlement`（`Settlement.cs:10`）。理由（02 報告 §5/§6 坐實）：無 map 時零常駐 pawn、零模擬成本；`Visitable`（`Settlement.cs:48-58`）/`Attackable`（`:60`）/交易/送禮/擊敗判定全套免費；數百個無 map 物件對世界 tick 幾乎零負擔（02 §9）。

| 面向 | 行為 | 機制 |
|---|---|---|
| 拜訪 | 非敵對時 float menu「拜訪哨站」→ 生成小圖、商隊進場 | 子類 override `GetFloatMenuOptions`，掛 sims-mode 的 ArrivalAction（§7），size 取自 OutpostTypeDef |
| 交易 | 與原版聚落一致：商隊停在哨站格上用交易 gizmo | 不動 Settlement 繼承（trader/`baseTraderKinds` 原樣）；與進圖拜訪並存，玩家二選一 |
| 攻打 | 攻擊 gizmo/float menu 改走自己的流程：小圖 + 原版關係懲罰 + 進場 | override 後不 yield 原版 attack，自己呼叫 `GetOrGenerateMap(tile, size, null)`（`GetOrGenerateMapUtility.cs:9`）+ `AffectRelationsOnAttacked`（`SettlementUtility.cs:61`，public static 可直接複用）+ `CaravanEnterMapUtility.Enter`（同 `SettlementUtility.cs:57` 寫法） |
| 地圖 | 小號聚落圖（預設 150x150，Def 可調），守軍規模低於聚落 | MapGeneratorDef 維持 `Base_Faction` → **與 sims-mode 共用整條生成線**，活聚落 patch 自動生效。守軍壓低的鉤子待 plan Task 0 驗證（候選順位：① 原版 points 參數可從 def/parent 傳入 ② `GetOrGenerateMap` 的 `extraGenStepDefs` 注入後處理 ③ 自寫削減 GenStep 附加其後） |
| 命名 | 「<母聚落名>哨站」 | 翻譯 key 格式化（`pas_outposts_NameFormat`），建立時定名 |
| 母聚落 | 持有 `parentSettlement` 引用 | `Scribe_References`；母聚落被毀 → 引用置 null、哨站保留為孤站（增益階段再處理孤站語意） |
| 擊敗 | 守軍清空即從世界移除 | 繼承 Settlement 擊敗線；Task 0 驗證 `SettlementDefeatUtility.CheckDefeated` 對子類的觸發點 |

已知互動（接受，列入 E2E 觀察）：子類會進 `Find.WorldObjects.SettlementBases`（`CaravanVisitUtility.cs:19-23` 即依此給交易）——任務系統（如 `QuestNode_GetNearbySettlement.cs:39`）可能把哨站當普通聚落選中，多為無害 flavor；若實測有害再在 O2 處理。

## 5. Def 體系（零寫死）

### OutpostTypeDef
| 欄位 | 型別 | O1 預設 | 用途 |
|---|---|---|---|
| `worldObjectDef` | WorldObjectDef | `pas_outposts_Outpost` | 圖標/材質/expandingIcon 載體 |
| `mapSize` | IntVec2 | 150x150 | 拜訪/攻打生成的地圖尺寸 |
| `defenderPointsFactor` | float | 0.4 | 守軍規模相對聚落的係數（機制見 §4） |
| `mapGeneratorDef` | MapGeneratorDef | `Base_Faction` | 留給 O2 換風味；O1 不動 |
| `weight` | float | 1 | profile 內抽選權重 |

O1 出一種：`pas_outposts_Type_Generic`。

### OutpostProfileDef（派系維度）
| 欄位 | O1 預設 |
|---|---|
| `factionDefs` / `techLevels` / `isDefault` | 同 sims-mode LifeProfileDef 三件套 |
| `countPerSettlement`（IntRange） | 1~3（每聚落哨站上限，建立聚落側資料時擲定） |
| `radius`（IntRange） | 2~4 格 |
| `types`（type+weight 清單） | Generic w1 |
| `spawnMtbDays` | 15（隨時間補鋪的 MTB，§6） |

Resolver 與 sims-mode 同模式（小 static 方法鏈，好 patch）：FactionDef Extension > factionDefs > techLevels > isDefault。**共用程式碼**：若 sims-mode 的 resolver 工具可泛化（plan Task 0 評估），抽用之；否則照模式重寫一份（資料源仍各自獨立）。派系停用：`OutpostDisabledExtension : DefModExtension` 掛 FactionDef 即可。永敵派系（海盜等）預設也鋪——純攻擊目標，`Visitable` 自動為 false。

## 6. 鋪設（兩段式，同一條核心邏輯）

每聚落上限在首次處理該聚落時擲定（profile 的 `countPerSettlement`），由 `WorldComponent_OutpostSpawner` 持久化（聚落→上限字典，`Scribe_Collections`）；開局 GenStep 與補鋪共用同一份資料。

核心方法（public static，供兩個觸發點與第三方呼叫）：`OutpostPlacer.TryPlaceFor(Settlement parent)` —— 解析 profile → 檢查該聚落現存哨站數 < 上限 → 半徑內挑有效 tile（原版新聚落標準：可建、非水/不可通行、未被占用；Task 0 確認 `TileFinder` 對應 API）→ `WorldObjectMaker.MakeWorldObject` + `SetFaction(parent.Faction)` + 定名 + `Find.WorldObjects.Add`（途中放置範式：02 報告 §4.3）。

- **開局**：`WorldGenStep_NpcOutposts`（WorldGenStepDef，order 排在派系聚落 gen step 之後，值 Task 0 查）——遍歷 NPC 聚落，每聚落鋪「上限的下半」（如上限 3 → 開局 1~2），留成長空間。
- **隨時間**：`WorldComponent_OutpostSpawner`——`WorldComponentTick` 節流（每 2500 tick 檢查一批；02 §7.2 範式），對每個未達上限的 NPC 聚落用 `Rand.MTBEventOccurs(spawnMtbDays, …)` 擲增生。世界自然長出哨站；中途裝 mod 的舊檔同樣生效（**免費的舊檔支援**，不需補鋪邏輯）。
- 不做：哨站消亡、執行期上限調整、母聚落被毀的連鎖清理（孤站保留）。

## 7. sims-mode 附帶交付：「真訪問」原版聚落

**坐實的前提修正**（2026-06-11 源碼查證）：原版 1.6 拜訪聚落**不生成地圖**——`CaravanArrivalAction_VisitSettlement.Arrived` 只發信（`CaravanArrivalAction_VisitSettlement.cs:37-43`），商隊停在格上用 gizmo 交易（`CaravanVisitUtility.cs:13-29`）；通用進圖選項要求 `HasMap` 且 NPC 聚落不顯示（`CaravanArrivalAction_Enter.cs:58-69`、`Settlement.cs:46`）；聚落唯一生圖路徑是攻擊（`SettlementUtility.cs:47` → 無 size 多載 → 世界初始尺寸，`GetOrGenerateMapUtility.cs:31-34`）。**因此 sims-mode P1 的活聚落目前只有攻打中立聚落與任務地圖兩個入口——本節補上正門。**

交付內容（commit 到 sims-mode-community，npc-outposts 經 assembly 引用共用）：
1. `CaravanArrivalAction_VisitMap`（pas.sims）：照 `CaravanArrivalAction_VisitSettlement` 骨架（60 行級），`Arrived` 改為 `GetOrGenerateMap(tile, size, null)` + `Notify_GeneratedPotentiallyHostileMap` 等同攻擊路徑的善後（`SettlementUtility.cs:51-57` 範式，但不呼叫 `AffectRelationsOnAttacked`）+ `CaravanEnterMapUtility.Enter`（不徵召）。size 參數化：原版聚落傳 `Find.World.info.initialMapSize`，哨站傳 OutpostTypeDef.mapSize。
2. `WorldObjectComp_VisitMap` + `WorldObjectCompProperties`：`GetFloatMenuOptions(Caravan)`（`WorldObjectComp.cs:45`，由 `WorldObject.cs:639` 迭代）yield「訪問據點（進入）」，條件 `Visitable`。
3. PatchOperation 把 comp 掛上原版 `Settlement` WorldObjectDef。**零 Harmony**——與 GenStep 注入同一招。
4. 哨站不走 comp（自己的 WorldObjectDef 沒掛），由子類 override 直接 yield 同一個 ArrivalAction → 無重複選項。

## 8. 已驗證技術點與待驗證清單

### 已坐實（引用見上文）
原版拜訪不生圖全鏈；`GetOrGenerateMap` 兩個多載與 size 控制權；`overrideMapSize` 存在但原版聚落路徑不吃（`WorldObjectDef.cs:25`、`SettleInEmptyTileUtility.cs:95` 為呼叫端自取範例）；`AffectRelationsOnAttacked` public static；`WorldObjectComp.GetFloatMenuOptions` 注入點；Settlement 子類進 `SettlementBases` 清單；無 map Settlement 零常駐 pawn（02 §5.1）。

### 待驗證（plan Task 0 對源碼 grep）
1. `Base_Faction` 守軍 points 的來源與壓低鉤子（§4 候選 ①②③ 擇一坐實）。
2. `SettlementDefeatUtility.CheckDefeated` 的呼叫點與對子類的觸發路徑。
3. `WorldGenStepDef` 的 order 值體系與派系聚落 step 名；以及 WorldGenStep 執行期間能否取得本 mod 的 `WorldComponent`（§6 上限字典在 gen 期就要寫入）。
4. `TileFinder` 的新聚落格有效性 API 確切簽名。
5. Settlement 子類自帶 WorldObjectDef 的必要欄位（`worldObjectClass`、expandingIcon 素材沿用原版聚落貼圖可行性）。
6. sims-mode resolver 工具可否直接泛化共用（不行就照模式重寫）。
7. `Settlement_TraderTracker` 對子類的初始化路徑（建構子 or SpawnSetup）。

## 9. 完成定義（O1 E2E）

1. 開新世界：NPC 聚落周圍出現哨站圖標（數量/半徑符合 profile），命名「<母聚落>哨站」。
2. 舊檔（無哨站）載入後隨時間自然長出哨站，直到各聚落上限。
3. 商隊右鍵中立哨站：有「拜訪」→ 進入 150x150 小圖，守軍少於聚落、**有 sims-mode 作息**（白天工作/晚上睡覺）。
4. 商隊停哨站格：可交易（原版 gizmo）。
5. 攻打哨站：小圖、關係懲罰與攻打聚落一致、清空守軍後哨站從世界移除。
6. 海盜哨站：無拜訪選項、可攻打。
7. 原版聚落（sims-mode 交付）：右鍵多出「訪問據點（進入）」→ 全尺寸圖 + 活聚落作息；原攻擊/交易選項不受影響。
8. 存讀檔：拜訪中存檔重讀無紅字；母聚落引用存活；孤站（dev 毀母聚落）讀檔無紅字。
9. 拔掉 sims-mode 時 mod 管理器顯示缺相依警告（modDependencies 生效），照常進遊戲不留紅字殘局。
10. `tests/healthcheck.py`（沿用 sims-mode 七檢架構）綠。
