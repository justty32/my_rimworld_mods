## 0. 一句話

玩家商隊訪問非敵對派系聚落（1.6 本體 visit settlement 機制）生成地圖時，聚落 pawn 不再傻站（原版全員掛 `LordJob_DefendBase` 只會守家），而是按**派系 → 角色 → 作息表**過自己的生活：白天各司其職、傍晚聚會社交、夜間回床睡覺、被襲擊時切換防禦。**整個體系全部資料驅動（XML Def），引擎零寫死，供其他 mod patch。**

## 2. P1 範圍

### 做
- 玩家訪問**非敵對**派系聚落 → 聚落 pawn 換掛 `LordJob_SettlementLife` 過生活。
- 角色分流 + 晝夜作息表（作息表完整版）：進場時按**當前時辰**直接就位（白天進來看到工作、晚上進來看到睡覺）。
- 被襲擊（玩家翻臉或其他威脅）→ Lord Trigger 切回原版防禦 toil；威脅解除切回生活。
- 派系維度：不同派系種類（部落/外邦/帝國…）可有不同的角色集與作息。
- 四層全 Def 化：派系檔案 / 角色 / 設施標記 / 行為（duty），引擎不含具體知識。

### 不做（YAGNI，留給後續階段）
- 玩家側互動（對話、租房、工作板）→ P2。
- 自訂地圖布局生成 → P3（v1 只「掃描成品地圖」，不控制生成）。
- 真實工作產出（`JobGiver_Work` 對非玩家 pawn 早退、WorkGiver 假設玩家 zone/所有權——報告 05 §3.5 定論：**假動作**）。
- 玩家殖民地側的任何功能 → P5。
- 敵對聚落（攻打）行為改動：保持原版 `LordJob_DefendBase`。

## 3. 核心架構

### 3.1 注入方式（方案 C：生成管線整合，零 Harmony）

XML `PatchOperation` 往原版聚落 MapGeneratorDef 附加自寫 **`GenStep_SettlementLife`**，排序在聚落建築與守軍生成之後。不取代原版布局生成（P3 才接管）。

`GenStep_SettlementLife` 流程：
1. 守軍派系對玩家**敵對 → 直接返回**（攻打場景，原版行為）。
2. **解析派系生活檔案**（`LifeProfileDef`，見 §4.1）。
3. **設施掃描**：跑 `FacilityTagDef` matcher 管線，結果存入 `MapComponent_FacilityRegistry`。
4. **角色分配**：跑 profile 的 `assignmentWorker`（預設按權重 + 設施門檻），產出 `Pawn → LifeRoleDef` 對應表。
5. **換 Lord**：把 pawn 從 `LordJob_DefendBase` 移除，掛進 `LordJob_SettlementLife`（持有對應表，`ExposeData` 存檔）。

### 3.2 生活 Lord 狀態機（全原版公開 API）

```
LordToil_SettlementLife ──Trigger_PawnHarmed / Trigger_BecamePlayerEnemy / Trigger_OnClamor──▶ LordToil_DefendBase（原版複用）
        ▲                                                                                        │
        └───────────────── Trigger_BecameNonHostileToPlayer ◀────────────────────────────────────┘
                                              （重襲可再轉 LordToil_AssaultColony，原版複用）
```

`LordToil_SettlementLife.UpdateAllDuties` + 每小時 tick：對每個 pawn 查 `角色 schedule × 當前時辰` → 發 `PawnDuty(duty, focus)`，focus 來自設施註冊表。**引擎只做查表，不含任何具體角色/時段/行為知識。**

## 4. 資料驅動四層（「盡量不要寫死」的落地）

> 設計原則：C# 是引擎，XML 是內容。任何具體的派系、角色、設施、時段、行為，都必須能被其他 mod 用 PatchOperation 或新增 Def 改掉，不動本 mod 的 C#。

### 4.1 `LifeProfileDef` — 派系生活檔案（派系維度）

決定「這個派系的聚落用哪套角色集」。

```xml
<pas.sims.LifeProfileDef>
  <defName>pas_sims_Profile_Tribal</defName>
  <roles>
    <li><role>pas_sims_Hunter</role><weight>2</weight></li>
    <li><role>pas_sims_Guard</role><weight>1</weight></li>
    ...
  </roles>
</pas.sims.LifeProfileDef>
```

**解析鏈（可插拔）**，由 `ProfileResolver` 依序嘗試：
1. FactionDef 上的 `DefModExtension`（派系 mod 作者直接指定 profile）。
2. `LifeProfileDef` 內宣告的 `<factionDefs>` 明示匹配。
3. `<techLevels>` 匹配（部落/中世紀/工業/太空…）。
4. 全域 default profile。

resolver 本身是 def 上可指定的 worker class，其他 mod 可整個換掉解析邏輯。

### 4.2 `LifeRoleDef` — 角色（含作息表）

```xml
<pas.sims.LifeRoleDef>
  <defName>pas_sims_Farmer</defName>
  <requiredFacility>pas_sims_FarmPlot</requiredFacility>  <!-- 地圖上沒田 → 此角色不分配 -->
  <fixedRoleForPawnKinds><li>...</li></fixedRoleForPawnKinds>  <!-- pawnKind 直綁角色，選填 -->
  <schedule>
    <li><from>7</from><to>17</to><duty>pas_sims_Duty_FakeWork</duty><focusFacility>pas_sims_FarmPlot</focusFacility></li>
    <li><from>17</from><to>22</to><duty>pas_sims_Duty_Social</duty><focusFacility>pas_sims_GatherSpot</focusFacility></li>
    <li><from>22</from><to>7</to><duty>pas_sims_Duty_Sleep</duty><focusFacility>pas_sims_Bed</focusFacility></li>
  </schedule>
</pas.sims.LifeRoleDef>
```

- 角色全集 = `DefDatabase<LifeRoleDef>`；新角色（酒保、僧侶、商販…）= 加 XML，零 C#。
- 作息表是角色的一部分，per-時段 patch 一個 `<li>` 即可改。
- 分配邏輯：profile 可指定 `assignmentWorker`（C# class，預設「權重 + 設施門檻 + pawnKind 直綁優先」），可被替換。

### 4.3 `FacilityTagDef` — 設施標記

```xml
<pas.sims.FacilityTagDef>
  <defName>pas_sims_Workbench</defName>
  <matchers>
    <li Class="pas.sims.FacilityMatcher_ThingClass"><thingClass>Building_WorkTable</thingClass></li>
  </matchers>
</pas.sims.FacilityTagDef>
```

- **matcher 可插拔**：內建 by-thingClass / by-defName 清單 / by-thingCategory；自寫 matcher 類或 patch matcher 清單皆可。
- **`FacilityTagExtension`（DefModExtension）**：建築作者在自家 ThingDef 直接明示標記，優先於自動偵測。
- 偵測結果集中在 `MapComponent_FacilityRegistry`，是唯一資料源——P3 生成時直接寫入、其他 mod 執行期增刪，都改同一份。
- v1 內建標記（皆為 XML 內容，非 C#）：床、餐桌/聚會點、工作台、農田（栽培作物簇）、巡邏點。

### 4.4 `DutyDef`（原版型別）— 行為本體

- 每個行為 = 一個**純 XML think node** 的原版 DutyDef（RimWorld 最可 patch 的結構），頂層統一保留：有敵就打 + `SatisfyBasicNeeds`（餓了吃、累了睡，原版子樹）。
- v1 內建 duty（XML 內容）：`Duty_FakeWork`（走到 focus 設施前播工作動畫，不產出）、`Duty_Patrol`、`Duty_Social`（`JobGiver_StandAndBeSociallyActive` 圍聚會點聊天）、`Duty_Sleep`、`Duty_HomeLife`。
- 自寫 C# 僅 2-3 個 JobGiver/JobDriver（假動作、指定床睡覺 fallback），以 think node 形式被 XML 引用——換行為 = patch duty 的 think tree，不動 C#。

### 4.5 C# 引擎清單（不含具體知識）

| 類別 | 職責 |
|---|---|
| `GenStep_SettlementLife` | §3.1 流程編排 |
| `MapComponent_FacilityRegistry` | 設施標記資料源（存檔） |
| `LordJob_SettlementLife` / `LordToil_SettlementLife` | 對應表持有 + 查表發 duty + 防禦切換 |
| `ProfileResolver`（預設實作） | §4.1 解析鏈 |
| `RoleAssignmentWorker`（預設實作） | §4.2 分配邏輯 |
| `FacilityMatcher_*`（內建三種） | §4.3 偵測 |
| `JobGiver_FakeWork` / `JobDriver_FakeWork`、`JobGiver_SleepAssignedBed`（fallback） | §4.4 行為原子 |

## 5. 風險與待驗證

| 項目 | 等級 | 對策 |
|---|---|---|
| NPC 夜間睡床：非殖民者找床可能被派系/指派檢查擋住 | **待實機驗證** | fallback：`JobGiver_SleepAssignedBed` 直接指定床下 `LayDown`，繞過 ownership |
| 假工作的視覺說服力 | 待實機驗證 | 報告 05 定論路線；RimCities 同款（它連假動作都沒有，只遊蕩） |
| 生活→防禦切換延遲（pawn 分散各處，集結比原版慢） | 注意（玩法面） | 衛兵角色常駐巡邏/守備 duty，作為快反部隊；`Trigger_OnClamor` 加速感知 |
| 與聚落生成 mod（VBGE/KCSG）相容 | 測試項 | GenStep 只掃描成品不假設布局；matcher 管線天然容納自訂建築 |
| 與 RimCities 類「已改聚落行為」mod 相容 | 已知限制 | 偵測到 pawn 已屬非 DefendBase Lord 時不接管（讓位） |
| MapGeneratorDef patch 點的正確 def 與 GenStep 排序 | writing-plans 坐實 | 對 `projects/rimworld` 源碼確認聚落地圖用哪個 MapGeneratorDef、守軍生成的 genStepOrder |
| 玩家離場地圖回收 | 無新風險 | v1 不做留宿，原版回收路徑不動 |

## 6. 技術棧與慣例

- C#（net48）+ XML Defs/PatchOperation；**零 Harmony**（v1 目標；若 MapGeneratorDef patch 路線實測有缺口才退回單一 postfix）。
- 無 mod 相依（visit settlement 為 1.6 本體功能）。
- defName 前綴：`pas_sims_*`（XML）/ namespace `pas.sims`（C#）。
- 對應 RimWorld 1.6；所有引用 API 於 writing-plans 階段對 `C:\code\mine\pas\projects\rimworld` 逐一附 path:line 坐實。

## 7. 完成定義（v1）

- [ ] 訪問非敵對聚落：pawn 按派系 profile 分角色、按時辰就位（白天工作/傍晚社交/夜間睡床）。
- [ ] 進場時辰正確：晚上進場直接看到睡覺，不從早上演起。
- [ ] 翻臉開打：全員切防禦 toil 反擊；威脅解除回到生活。
- [ ] 攻打入口（敵對）行為與原版完全一致。
- [ ] 四層 Def 可 patch 性驗證：用一個測試 patch 新增一個角色 + 改一段作息 + 標記一個自訂建築，全程不改本 mod C#。
- [ ] 至少兩個內建 profile（default + tribal）證明派系維度生效。
- [ ] 存讀檔：訪問中存檔再讀，角色對應表與作息不壞。
- [ ] 實機端到端驗證 + 靜態健檢全綠。
