# faction-politics P1 設計 spec（反叛→分裂一條龍）

> 狀態：已通過使用者核准（2026-06-11 brainstorm Q&A 四決策 + 設計案核准）。
> 可行性依據：`docs/2026-06-11-feasibility/`（全 API 已靜態驗證，含對來源報告的 5 處修正）。

## 1. 目標

NPC 派系內出現**具名反叛者 NPC**：駐在該派系某聚落（玩家拜訪/攻打時找得到、殺得掉），反叛進展隨時間推進，達閾值時**分裂出新派系**——部分聚落（含其衛星哨站）倒戈易主、與母派系敵對。世界從靜態派系表變成會自己長出政治事件的活物。

## 2. 範圍

### P1 做
- 每個合格派系 1 個反叛者 NPC（world pawn KeepForever + 駐地聚落 redress 橋）。
- 反叛進展（profile 驅動速率、死亡歸零+冷卻重生=鎮壓玩法）。
- 分裂編排（hidden 生成→倒戈→揭示→敵對→letter），動態派系總數上限。
- Rim War 反射 bridge 骨架 + npc-outposts 條件 assembly bridge（哨站跟隨倒戈）。
- 健檢、第三方擴充示範、繁中/英翻譯。

### P1 不做（後階段）
- 安撫/煽動等玩家對反叛者的互動（P2，等 sims-mode 互動基建）。
- 同盟/合併/通用生命週期引擎（P2+）。
- 分裂時 Rim War 戰力數值轉移、哨站增益母聚落（待使用者提供參考 mod 的另案）。
- 真刪派系、活躍/休眠分層（原版量級下不需要）。

## 3. 技術棧與慣例

C#（net48）+ XML Defs，**零 Harmony**（全 public API，feasibility `02`/`03` 驗證）。
資料夾 `faction-politics/`，packageId `pas.politics.community`，namespace `pas.politics`，defName 前綴 `pas_politics_*`。每 C# 檔 ≤200 行。
相依：**無硬相依**（sims-mode 僅推薦、npc-outposts/Rim War 軟橋）。對應 RimWorld 1.6，反編譯權威源 `C:\code\mine\pas\projects\rimworld`。

## 4. Def 體系

```
RebellionProfileDef : Def            // 派系如何反叛
  List<FactionDef> factionDefs       // 綁定派系（可空）
  List<TechLevel> techLevels         // 或按科技層（可空）
  bool isDefault                     // 全域恰好 1 個
  FloatRange progressPerDay = 0.2~0.6   // 每日進展（每反叛者擲定一次存 record）
  float threshold = 100              // 分裂閾值
  FloatRange defectFraction = 0.3~0.5   // 倒戈聚落比例（保底母留 1）
  float respawnDelayDays = 20        // 反叛者死後重生冷卻
  int minSettlements = 2             // 派系至少 N 聚落才養反叛者

PoliticsSettingsDef : Def            // 全域設定，恰好 1 個實例
  int maxDynamicFactions = 5         // 動態派系總上限
  int checkIntervalTicks = 2500      // WorldComponent 輪詢間隔

PoliticsProfileExtension : DefModExtension { RebellionProfileDef profile }   // FactionDef 直綁（最高優先）
PoliticsDisabledExtension : DefModExtension { }                              // 停用某派系
```

解析鏈（比照 npc-outposts）：`Disabled → null`；`ByExtension ?? ByFactionDef ?? ByTechLevel ?? Default`。
合格派系：humanlike、非 player、非 Hidden、非 defeated、非 temporary、聚落數 ≥ minSettlements、profile 非 null。

## 6. 資料流

```
WorldComponent tick (每 2500)
 ├─ EnsureRebels：合格派系無 record → RebelSpawner 生成（挑隨機聚落為駐地）
 ├─ 自癒：rebel 不在 world pawns（且未 spawned）→ 補 PassToWorld；
 │        不在駐地清單 → 補 Add；駐地易主/被毀 → 換駐地；rebel 死 → 歸零+冷卻
 ├─ 推進：progress += ratePerDay × interval/60000
 └─ 觸發：progress ≥ threshold 且動態派系數 < 上限 且 rebel 未在地圖上
      → FactionSplitter.Split(record)
          1 hidden 生成同 def 新派系 → 2 Add → 3 rebel 升首領改隸
          4 倒戈（排除 IsSatellite，保底留 1，逐筆發 SettlementDefected）
          5 揭示 → 6 GoodwillToMakeHostile 敵對 → 7 letter
      → record 移除；母派系經冷卻後可再養新反叛者
```

## 7. 存讀檔

- `Scribe_Collections.Look(records, LookMode.Deep)`；record 內 faction/rebel/settlement 全 `Scribe_References`。
- `spawnedFactions`（動態派系計數）`LookMode.Reference`。
- PostLoadInit：剪 null（聚落被毀/反叛者被清的殘引用），比照 npc-outposts 防 null-key 紅字。
- 舊檔中途裝 mod：`FinalizeInit(fromLoad)` 跑 EnsureRebels 自動補發——免新開檔。

## 8. 信件與翻譯

- 分裂：`pas_politics_SplitLetterLabel/Text`（NegativeEvent，lookTarget=反叛者所在/首個倒戈聚落）。
- 反叛者出現（首次生成該派系反叛者）：`pas_politics_RebelEmergedLetter*`（NeutralEvent，低頻）。
- 原版敵對信以 `canSendMessage:false, canSendHostilityLetter:false` 壓掉，避免雙信。

## 9. 完成定義（E2E 於計畫 task 收錄）

開局/舊檔補發反叛者 → 拜訪駐地見到本人 → 擊殺=歸零+冷卻重生 → 達標分裂（letter、新派系入列、聚落+哨站易主、母新敵對）→ 存讀檔完整 → 上限觸頂停發 → 無 Rim War/無 npc-outposts 環境 log 乾淨 → 健檢綠。

## 10. 設計期修訂記錄

- Rim War bridge 由「loadFolders 條件 assembly」改為「主 DLL 反射」——本機無 Rim War DLL/反編譯源，無法編譯期引用；反射骨架 + 簽名校準待使用者供檔（feasibility `04`）。
- 敵對設定順序定為「揭示後走 goodwill 路徑」——hidden 期間 `HasGoodwill=false` 使 goodwill 路徑無效；`SetRelation` 反向 baseGoodwill 不複製故棄用（feasibility `02`）。
- 分裂觸發加前置「反叛者不在任何地圖上」——避免 redress 在場期間 SetFaction 的敵我反轉未定行為（feasibility `05` 風險 5）。
