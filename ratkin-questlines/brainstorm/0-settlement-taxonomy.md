# 據點類型細化（VOE 骨架 × 鼠族主題）

> 2026-07-18 綜合。把 §3 的五大寬泛類，用 Vanilla Outposts Expanded（VOE）系列的 outpost 功能分類當骨架，切成準確子類。
> 這是 Phase-1 內容複製的**精準靶**：每個子類 → 哪些訪客/委託/意外。

## VOE 帶來的兩個關鍵設計原則（採納）

1. **身份＝功能，不是標籤**：VOE 用三層疊加定義一個據點「是什麼」——①入駐門檻（`RequiredSkills` 技能／`AllowedBiomes` 地形／`MinPawns`）②產出公式（`Amount = 基礎 + 每人 + Σ技能×等級`，高技能解鎖高階產物）③`TicksPerProduction` 分「資源型 vs 服務型」。**身份由「建築/地形前提＋派駐 pawn 技能總和→產出/服務」決定**。
   → **直接精煉我們的 §2 衍生式身份**：C# colony profiler 應照同一邏輯，讀殖民地**主導技能＋關鍵建築＋biome**推導身份（而非只看財富/房間）。使用者自製 `voe-outpost-enhancement` 也印證：類別(worldObjectClass)決定行為、類別內用倍率/門檻做程度差異。
2. **資源型 vs 服務型 → 對映任務鉤子類型**：資源型據點（農/貿/產）→ **供貨/交易**任務；服務型（防禦/砲兵/傭兵/使館/教會）→ **契約/戰鬥/外交**任務。

## 規模軸（跨所有類型）

VOE 的 `Outpost_Town`（招募路過訪客為永久居民，需 MinPawns≥5＋附近已有聚落）**就是「村莊→城鎮」的機制原型**，驗證我們的規模進程軸。各子類都可有量級：**前哨 → 村莊 → 城鎮 → 城市**，量級由財富/人口門檻快照分級（純 XML 可做，見 §2），高量級解鎖更大/更多訪客與委託。

## 落地用法
- **Phase-1 內容複製時**，以「群→子類」為單位鋪線，每子類至少 1 條 F1 對話插曲奠定該身份的世界感，再視需要加委託/戰鬥線。
- **F7 身份系統**照 VOE 邏輯設計：profiler 讀主導技能＋關鍵建築＋biome→推導子類身份旗標；資源型/服務型二分決定給供貨型還是契約型委託。
- 未被 57 條涵蓋的空格（牧場、漁村、戲班、使館、監獄、邊境…）是**下一輪點子擴充**的目標。
